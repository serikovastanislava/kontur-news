# Контур — новостной портал

Актуальная версия проекта: **v11**.

Проект представляет собой новостной портал с React/Vite-фронтендом и Django REST backend. Новости, полученные парсером, сохраняются в базе данных и используются для ленты, поиска, карточек, главного материала и обсуждений.

## Что изменено в v11

### 1. Блок «Коротко» удалён

Старый блок `Коротко` из правой колонки полностью убран вместе с его компонентом и стилями.

На его месте теперь рекламная плашка:

> **Здесь могла бы быть ваша реклама**

Плашка оформлена как самостоятельный виджет и не содержит тестовых новостей.

### 2. Поиск работает непосредственно по базе данных

Поиск больше не использует демонстрационный массив статических материалов.

Фронтенд обращается к:

```text
GET /api/news/search/?q=запрос&limit=30
```

Backend ищет по модели `NewsItem` в следующих полях:

- `title` — заголовок;
- `content` — содержимое распарсенной новости;
- `summary` — краткое содержание;
- `source` — источник;
- `category` — категория.

Поиск выполняется непосредственно в БД, поэтому найденные результаты соответствуют реально загруженным парсером новостям.

Если строка поиска пустая, endpoint возвращает последние материалы из БД.

### 3. Курс валют обновляется каждые 10 минут

Виджет валют получает данные через:

```text
GET /api/news/currency/
```

Источник — ЦБ РФ.

Изменено:

- frontend обновляет данные каждые **10 минут**;
- backend-кэш курса действует **10 минут**;
- запрос выполняется без browser cache.

Важно: официальный источник ЦБ может публиковать новые значения реже, чем каждые 10 минут. В таком случае портал повторно проверяет источник, но значение останется прежним до появления нового официального курса.

### 4. Добавлены обсуждения новостей

В интерфейсе появился отдельный значок обсуждений в виде облачка. Использована форма и визуальная идея Bootstrap Icons `chat-dots`.

При нажатии открывается выезжающая справа панель.

В панели отображаются:

- текущие новости из БД;
- категория новости;
- время публикации;
- количество сообщений в обсуждении.

При выборе новости открывается отдельный чат именно этой новости.

### 5. Права пользователей в обсуждениях

Чат публично читаемый:

- незарегистрированные посетители могут видеть новости и все сообщения;
- зарегистрированные пользователи могут отправлять сообщения;
- backend дополнительно проверяет JWT-аутентификацию перед созданием сообщения.

То есть ограничение записи реализовано **на сервере**, а не только скрытием кнопки в React.

Endpoint чтения:

```text
GET /api/news/<news_id>/discussion/
```

Endpoint отправки:

```text
POST /api/news/<news_id>/discussion/
```

Тело запроса:

```json
{
  "body": "Текст сообщения"
}
```

Максимальная длина сообщения — 2000 символов.

Список текущих обсуждаемых новостей:

```text
GET /api/discussions/?limit=20
```

### 6. Обновление чата

Для чата используется polling:

- список новостей обновляется каждые 30 секунд;
- открытый чат проверяет новые сообщения каждые 5 секунд.

WebSocket/Redis/отдельный realtime-сервер для этой функции не требуется.

### 7. Карточки новостей

Сохранились предыдущие изменения:

- заголовки карточек имеют одинаковую высоту;
- длинные заголовки ограничиваются двумя строками;
- лишний текст визуально заменяется многоточием;
- полный заголовок и содержание доступны после открытия статьи;
- интерактивные элементы имеют `cursor: pointer` и hover-состояния;
- статьи открываются внутри сайта через Article Reader.

### 8. «Мнение редакции» и мультимедиа

Нижний блок продолжает использовать равные колонки:

- «Мнение редакции»;
- «Мультимедиа».

Карточки редакционных материалов имеют стабильный размер и не разъезжаются при изменении длины заголовков.

### 9. Изображения

Для новостных материалов сохраняется система fallback-изображений.

Она используется, если:

- источник не предоставил изображение;
- изображение не подходит по условиям проекта;
- необходимо показать фирменную заглушку.

### 10. Английская версия

Переключатель языка продолжает менять интерфейс на английский.

Для статьи на английском языке Article Reader отдельно запрашивает перевод заголовка и содержания через:

```text
POST /api/news/translate/
```

Длинные тексты переводятся частями, чтобы не превышать ограничение публичного endpoint перевода.

## Frontend

Основные технологии:

- React 18;
- Vite;
- JavaScript/JSX;
- Lucide React для большинства интерфейсных иконок;
- SVG-иконка Bootstrap-style `chat-dots` для обсуждений.

Основные компоненты:

- `App.jsx` — корневой интерфейс;
- `Header.jsx` — верхняя навигация и поиск;
- `Sidebar.jsx` — боковая навигация;
- `SourcesFeed.jsx` — новости из backend;
- `HeroNews.jsx` — главный материал;
- `PopularGrid.jsx` — популярные материалы;
- `Editorial.jsx` — мнение редакции и мультимедиа;
- `RightRail.jsx` — правая колонка;
- `AdBanner.jsx` — рекламная плашка;
- `CurrencyWidget.jsx` — курсы валют;
- `DiscussionsDrawer.jsx` — панель и чаты обсуждений;
- `ModalRoot.jsx` — Article Reader, поиск, авторизация и другие модальные окна.

## Backend

Backend построен на:

- Django;
- Django REST Framework;
- SimpleJWT;
- PostgreSQL в Docker;
- SQLite для быстрого локального запуска.

Основная модель новостей:

```python
NewsItem
```

В ней находятся заголовок, URL, содержание, категория, источник, изображение, дата публикации, просмотры и другие данные.

Обсуждения хранятся в:

```python
DiscussionMessage
```

Связь:

```text
NewsItem 1 ─── N DiscussionMessage N ─── 1 User
```

# Парсер новостей

Распарсенные материалы должны сохраняться в `NewsItem`.

Именно эта таблица является источником для:

- ленты новостей;
- поиска;
- обсуждений;
- главного материала;
- карточек категорий;
- популярных материалов;
- статистики просмотров.

При добавлении нового источника желательно сохранять:

- уникальный URL;
- заголовок;
- полный текст;
- краткое содержание;
- источник;
- категорию;
- дату публикации.

# Поиск

Поиск не зависит от `src/data/news.js`.

Запрос:

```text
/api/news/search/?q=санкции
```

Backend разбивает запрос на слова и требует совпадение каждого слова хотя бы в одном из поисковых полей новости.

Например:

```text
санкции компании
```

будет искать новости, где встречаются оба термина в заголовке, содержании, категории, источнике или summary.

# Обсуждения: логика доступа

Посетитель без аккаунта:

```text
видит список новостей
        ↓
открывает обсуждение
        ↓
читает сообщения
        ↓
для отправки → авторизация
```

Авторизованный пользователь:

```text
открывает новость
        ↓
читает обсуждение
        ↓
пишет сообщение
        ↓
POST /api/news/<id>/discussion/
```

Сервер не доверяет состоянию React: даже если вручную отправить POST без токена, backend вернёт `401`.

# Очистка проекта

В проекте не хранятся:

- `node_modules`;
- `dist`;
- `__pycache__`;
- `.pyc`;
- временные архивы;
- старые неиспользуемые компоненты.

После удаления `Коротко` также удалены его frontend-компонент и связанные с ним стили.

Старые демонстрационные данные поиска удалены из клиентского поискового контура: поиск теперь использует реальную БД.

# Примечание о realtime

Текущая реализация обсуждений использует HTTP polling. Это намеренное решение для простоты развёртывания.

Если в дальнейшем потребуется большое количество одновременных пользователей, обсуждения можно перевести на Django Channels/WebSocket + Redis без изменения модели `DiscussionMessage` и публичной структуры данных.
