# Контур

## Источники новостей

Автоматический парсер теперь работает с четырьмя источниками:

- **ТАСС** — `https://tass.ru/`, RSS `https://tass.ru/rss/v2.xml`;
- **Коммерсантъ** — `https://www.kommersant.ru/`, RSS `https://www.kommersant.ru/RSS/news.xml`;
- **АиФ** — `https://aif.ru/`, RSS `https://aif.ru/rss/googlearticles`;
- **ИА «Панорама»** — HTML-парсинг `https://panorama.pub/news`.

Для ТАСС, Коммерсанта и АиФ предпочтительно используется RSS: это уменьшает количество запросов к сайтам. Страница самой статьи запрашивается только для нового URL, чтобы получить метаданные: автора, дату, краткое описание и `og:image`.

Панорама остаётся отдельным источником и не получает суффикс «сатира». В общей API-ленте материал Панорамы вставляется на каждую 20-ю позицию, если такой материал доступен.

## Контент и изображения

Проект хранит:

- заголовок;
- ссылку на оригинальную публикацию;
- источник;
- автора;
- дату;
- короткий фрагмент/описание;
- URL изображения, указанного самой страницей источника.

Полные тексты сторонних публикаций и копии сторонних фотографий намеренно не сохраняются. Для полного текста читатель переходит на оригинальный материал по `url`. Это также предотвращает повторное копирование большого объёма контента при каждом цикле парсера.

## Автоматическое обновление

Парсер запускается отдельным worker-контейнером:

```bash
python manage.py parse_news --loop --interval 60
```

React обновляет API каждые 30 секунд.

## Локальный запуск

```bash
python -m venv .venv
.venv\\Scripts\\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py check
python manage.py parse_news
python manage.py runserver
```

## Обновление изображений

Для уже сохранённых материалов без изображения:

```bash
python manage.py refresh_news_images
```

Для принудительного обновления всех изображений:

```bash
python manage.py refresh_news_images --all
```

## Миграции

Текущая модель уже содержит поля `summary`, `image_credit`, `category`, `importance_score`, `published_at` и `views`. После получения обновлённого проекта достаточно выполнить:

```bash
python manage.py migrate
```

## Замена старых источников в существующей базе

Если база уже содержит старые материалы РИА, РГ или БНК, они не удаляются автоматически. Для очистки выполните:

```bash
python manage.py remove_old_sources --yes
```

После этого:

```bash
python manage.py parse_news
```


## Исправление изображений

Изображения новостей теперь не отдаются браузеру напрямую с Telegram, Unsplash или Wikimedia.
Парсер сначала получает фотографию из публикации/OG metadata, затем при отсутствии подходящей
картинки ищет тематическую иллюстрацию в Wikimedia Commons по заголовку и контексту статьи,
скачивает её в `MEDIA_ROOT` и только после этого отдаёт фронтенду локальный `/media/...` URL.

Для старых записей контейнер `parser` при старте автоматически проверяет до 200 отсутствующих
или битых изображений. Полную переработку можно запустить вручную:

```bash
docker compose run --rm parser python manage.py refresh_news_images --all
```

В Docker `/app/media` общего backend/parser volume подключён к nginx как `/media/`, поэтому
локальные изображения доступны браузеру даже когда внешний источник временно недоступен.


## Обновление изображений и мультимедиа

После миграций новые публикации автоматически:
- берут `og:image`/`twitter:image`;
- если изображения нет, ищут тематическую иллюстрацию через Openverse, затем Wikimedia Commons;
- сохраняют изображение локально в `/media/`;
- формируют короткое резюме по сути материала;
- ищут реальное видео из оригинальной статьи или публичный тематический видеоматериал Wikimedia Commons.

Для уже загруженных новостей:

```bash
docker compose run --rm parser python manage.py refresh_news_images --all
docker compose run --rm parser python manage.py refresh_multimedia --limit 200
```

Видео в мультимедиа открывается как настоящий HTML5 video/YouTube/Vimeo player с фиксированным соотношением 16:9, поэтому его не растягивает и не деформирует.

## Контент-заглушки и мультимедиа

- Парсер больше не использует старые bundled news-фотографии как fallback.
- При отсутствии фото оригинальной статьи он ищет открыто лицензированное изображение через Openverse, затем Wikimedia Commons.
- Команда `seed_topic_stubs` создаёт по 10–20 уникальных демонстрационных публикаций на каждую категорию и подбирает отдельные изображения из Openverse.
- В `docker-compose.yml` parser запускается с `--seed-topic-stubs 12`, поэтому после первого старта в каждой категории будет до 12 уникальных заглушек.
- Старые изображения из `src/assets/crops` удалены.
- Нижний блок «Мультимедиа» использует реальные 16:9 WebM-файлы Wikimedia Commons с лицензиями CC и переключатель видео. Источники и лицензии указаны под плеером.
- Конфликт миграций устранён: оставлена только `0013_alter_newsitem_video_credit.py`.

Для ручного пересоздания заглушек:

```bash
docker compose run --rm parser python manage.py seed_topic_stubs --count 12 --force
```
